# TestFix Lab 操作指南

打开本地实验室：<http://127.0.0.1:8765/lab>。页面用于启动真实实验、观察总控与员工协作、查看证据和亲手输入验证；3D 效果不参与验收判定。

公开源码不包含本机历史报告、模型原始轨迹和交付 ZIP。新克隆的环境需要按 README 配置并启动实验，随后才有该机器自己的运行记录。

## 先查看一次完整记录

在“查看运行”中选择记录，点击“载入记录”。顶部会标出“历史实测记录 · 当前未调用模型”或正在观测的真实运行。载入历史记录不会重新调用模型，也不能当作本次新实验。

协作图支持拖动旋转、滚轮缩放、点击节点。点总控、能力或员工节点，在右侧查看实际状态、Skill 与结果。“重置视角”恢复视角；“切换平面”切换平面依赖图，再点“切换 3D”返回。WebGL 不可用时会显示 CSS 3D 降级视图，仍可点击节点查看证据。连接线表示任务依赖，不能据此判断功能已经通过。

在下方依次查看“测试结果”“需求覆盖”“测试步骤”“代码补丁”“执行事件”“模型与预算”。通过与否以独立验收、原有回归、构建与实际启动记录为准。可下载“JSON 报告”“Markdown”和“工程与证据 ZIP”；尚未形成交付的记录不会提供可用交付包。

原注册验收结束后仍可追加独立检查。若发现回归，页面会显示“原验收通过；追加检查未通过”，保留原五套件分数，并单列候选 SHA 绑定的失败证据。不要只看运行状态 completed 或已通过的用例数；还应检查追加结论。CSV 探针只证明你刚输入的这个场景。

## 自己启动真实测试

左侧“选择工程”目前有两个已注册的完整工程：

- **rich-cli**：修复真实 CSV/TSV 方括号文本被错误解析为样式的问题，保留原有打印和导出功能。
- **Flaskr**：在原版博客上实现详情、搜索与分页，检查原有登录、文章操作和 SQLite 持久化。

选择工程会填入默认需求。可以在“描述你的需求”中调整表述与业务输入，并保留该工程的已注册功能范围、允许修改文件和验收合同。现有入口不能据此宣称已经支持任意 GitHub 工程或任意新功能。

在“模型与资源预算”中检查模型服务、请求模型、并发槽位、修复轮数、时间和 Token 上限，再点击 **“启动真实测试”**。这会创建新运行并调用现有配置的真实模型，消耗相应服务额度。请求模型名与提供方返回的型号分开记录；服务未返回实际型号时不能将请求名当成型号证明。

启动后顶部显示“本次新启动 · 真实模型运行”。观察状态随真实记录更新，点节点核查模型动作、工具回执和交接。规划完成或生成补丁都不是最终成功；失败与未执行步骤应保留，等待最终验收结论再检查交付物。

## 不调用模型，亲手对比原版和修复版

载入一个**验收通过且交付证据完整的 rich-cli 记录**，打开“自己输入测试 ↗”。选择“CSV 表格”，输入例如：

```csv
name,value
[bold],[/not-opened]
plain,[red]literal[/red]
```

点击“运行原版与修复版 ↗”，查看两侧真实 CLI 子进程的退出码与输出。还可以切换“保留原有 --print 样式解析”检查原有样式功能。探针不调用大模型，输入和输出有独立回执；它是人工追加检查，**不计入原始验收分数，也不会改写历史成绩**。该按钮不适用于 Flaskr、未通过或缺少交付证据的运行。

“CSV · 同时 head=1 / tail=1”以固定参数重现追加发现的兼容性问题。默认使用普通 CSV，原版与正确候选都应退出 0，仅显示第一行数据。可将它用于检查 66c 的失败候选与后续修复，分别查看实际结果。

## 查看后续测试数据

页面底部“实验数据集”按采集、适配和可运行状态展示数据。在 SWE-bench Lite 或 BugsInPy 卡片展开“查看已采集任务”，可以查看公开任务预览及固定版本信息。预览不包含参考补丁、测试补丁或独立评测源码。

**已采集不等于已适配，更不等于已经修复成功。** 这些预览目前不能直接启动仓库实验，仍需环境复现和独立评测适配。HumanEval 是函数级辅助集，不能当作完整工程成绩。采集清单、预选规则和指标定义见[测试数据与评测协议](benchmark-datasets.md)。

比赛排练、应展示的证据与华为平台实际采用要求，见[参赛演示与可复核验收](contest-demo-playbook.md)。历史记录可用于明确标注的演示备份；正式展示仍应让观众核对原版故障、真实派工、补丁、独立验收和安装后的业务输出。
