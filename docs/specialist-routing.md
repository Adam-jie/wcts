# 专业 Agent 分工与执行边界

本轮在原有九项核心能力上增加十份自建专业 Skill，不替换规划、测试生成、诊断、评审和独立验证。它们位于 `testfix/specialist_library/`，由版本化目录及 SHA256 绑定。专业名称表示同一真实 LLM 员工调用所采用的能力组合，并不表示十个模型永久同时运行，也不表示新增十种设备执行器。

| 专业 Skill | 处理内容 | 当前实现调用条件 |
| --- | --- | --- |
| software | 包、模块、CLI、边界行为 | 注册软件适配器；原有构建与验收关卡 |
| javascript | JS/TS、异步、构建接口 | Node 构建和浏览器适配器，当前缺失时阻塞 |
| frontend | 模板、表单、样式、交互契约 | Flaskr 支持服务端模板；JS 页面另需浏览器适配器 |
| threejs | 场景、相机、拾取、动画、资源释放 | WebGL 浏览器适配器，当前缺失时阻塞 |
| backend | 路由、API、认证、事务交接 | Flaskr 的真实 HTTP 验证适配器 |
| database | SQL、事务、SQLite 持久化 | Flaskr SQLite；PostgreSQL/Redis/ORM 不因此自动支持 |
| mcu | 裸机/RTOS、固件、外设 | 固件构建及设备适配器，当前完整工程流程缺失时阻塞 |
| mpu | 嵌入式 Linux、交叉构建、设备树 | 目标构建及设备适配器，当前缺失时阻塞 |
| protocol | UART/SPI/I2C/CAN、帧与恢复 | 工程级协议执行适配器，当前缺失时阻塞 |
| integration | 跨模块接口与交接 | 注册元数据指定；仍保留独立验收角色 |

既有 `/hardware` 的协议功能测试是独立能力，不代表本流程已具备任意板卡的固件补全、编译和实板验收。当前固定规则只识别部分明确的源码信号；它不是完整语义分析器。别名调用、间接依赖、彻底删空的逻辑可能需要补充注册元数据和人工核对。

## 实际流程

1. CodeAgent 总控将已注册需求分成有文件范围、需求编号和依赖的员工任务；默认最多 32 项，可由 `TESTFIX_MAX_WORK_ITEMS` 配置。
2. 宿主只检查该任务分配的公开路径及源码信号，不因项目安装了依赖而加载全部 Skill。需要新文件时须在已注册修改范围内。删空代码可通过注册需求中的 `specialist_ids` 提示必需专业。
3. 结果分为 `ready`、`blocked`、`needs_discovery`；无关专业列入 `not_applicable`，其 Skill 文本不进入员工提示词。缺执行环境不回退为“通用 Agent 成功”。探索任务可只读分析不支持的技术，交接缺失条件。
4. 前驱交接通过 CodeAgent 检查后才进入就绪队列；出度、关键路径等仅排序就绪任务。CP-SAT 约束依赖顺序、可用员工、预算、并发和同文件写冲突。
5. 员工每次调用都重新计算当前源码分工，模型适配器再核对并加载可信 Skill 原文。模型提议动作，WCTP 执行模型批次，宿主串行执行受限文件工具与提交。
6. 员工交回结果后，CodeAgent 根据本项任务、关联需求、实际工具观察和当前代码做交接检查；不充分时将具体意见退回该员工，只有批准后才释放依赖。单个员工只需完成自己的任务，最终仍需冻结验收、原有回归、构建及注册真实运行检查。模型判断交接就绪不是功能正确的证明。

不同文件的员工可以在依赖满足时并行，宿主将补丁依次合并并保留实际检查；文件不同并不保证接口或行为没有语义冲突，公开测试、评审与最终验收仍然必需。模型交接检查消耗调用预算，在预算或步骤耗尽时保留失败结果。

同一任务修改多个技术层时加载组合 Skill，仍只有任务指定的文件权限；不能因选中“数据库 Agent”获得数据库访问权限。Skill 中的质量要求是提示约束；动作白名单、文件范围、哈希、预算和验收隔离才是宿主强制约束。

## 查看分工

```powershell
uv run python -m testfix.cli specialists --project Project/flaskr
```

或访问本地 `GET /api/project-specialists?project_id=Project%2Fflaskr`。这是注册基线的只读预览，不调用模型、不执行项目、不写补丁。原有真实执行命令为：

```powershell
uv run python -m testfix.cli complete-project --project Project/flaskr --provider codex_cli --request "完成已注册的文章详情、搜索和分页功能，保持原有行为"
```

运行 JSON 的 `collaboration.rounds[].specialist_assignments` 记录分配原因、无需加载的专业和缺失能力。模型请求记录包含实际选中 Skill 的文本，调用 trace 绑定专业库哈希。报告列出专业分工和阻塞项。以上命令中的真实执行不是本轮单元检查已经完成的实验。

AgentArts 高代码 Runtime 支持固定的总控任务计划及员工动作 Schema，并检查专业 Skill 目录快照。远端重新加载自己的可信文件，不信任客户端提示词；专业目录不一致拒绝调用。此处是部署代码和本地契约检查，不能作为已经部署上云或真实 MaaS 调用的证据。

## MCTS 的位置

专业路由作为“按源码证据选择专业 + 依赖图 + CP-SAT”的基线，现已接入隔离候选工作区与 UCT 多树搜索，见 [可执行搜索与实验口径](mcts-engineering.md)。可使用 `--search none`、`--search mcts`、`--search forest` 选择模式。

独立验收不反复反馈给搜索器。用同样任务、模型和预算比较固定分工、当前基线、单树和多树，才能报告成功率、回归破坏率、耗时与成本；规划估计分数不能冒充真实修复效果。硬件编译和实板适配边界仍按上表明确处理。
