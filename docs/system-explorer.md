# 整棵分支展开架构 04

桌面软件中打开“架构模型”。本版依据用户确认的结构，将系统归为三大主模块，其他技术与能力均为其内部组成。模型保留 3 个主模块和 18 项直属能力，并增加 38 项更深层细分，共 59 个可选择节点。这些是职责、角色与算法步骤的分组，不表示 59 个模型常驻或并发运行。

| 主模块 | 内部能力 |
| --- | --- |
| CodeAgent 主控 | 需求理解与任务规划；专业 Agent 分配；ILP 约束与就绪排序；UCT 单树 / 多树搜索；LLM 与 AgentArts 接入；汇总、预算与二次分配 |
| 多 Agent 生成与补全 | 仓库与功能缺口分析；任务拆解与 Skill 分配；专业 Agent 协作实现；MCTS / UCT 候选空间树；诊断、补全与代码评审；集成交接与再次修改 |
| 自动化测试 | 测试步骤与用例生成；WCTP 连线与执行工具；循环与多数据测试；产品运行与质量核验；独立验收与回归保护；证据报告与工程交付 |

主控分配任务，生成补全提交候选代码，自动化测试真实执行并回报主控。主控根据公开失败证据进行二次分配。最终独立验收内容不向补全模型回流。

## 交互

- 单击任何一个主模块，会一次显示它的全部后代，包含所有层级。多 Agent 主模块一次展开 44 项内部能力；连同三个主模块，场景中共显示 47 个节点。
- 左侧完整树、右侧完整功能清单和三维场景同步展开。点击具体 Agent 或算法只改变高亮与详情，其他分支内容保持展开。
- 三维部件按六个直属阶段分组铺开，细分节点使用不同坐标，保留层级及算法反馈连线。相机按照窗口宽高与完整分支范围自动取景，普通点选不自动聚焦裁切。
- 底部或右侧“一键收拢”明确关闭整棵分支；再次“一键展开”全部打开。重复点击同一主模块只恢复完整取景，不会把它收起。
- 保留旋转、缩放、平移、明确的聚焦与复位。所有已展开节点都有标注；小窗口可放大和平移查看。完整树和清单可以滚动阅读，无需逐个打开。
- 恢复用户截图中的同画布铺开布局：三个主模块名称与六列直属阶段、细分 Agent 和算法一同展示。点击名称会高亮相应模型和右侧详情，不折叠其他名称。底部保留连线、标注和自动旋转开关。
- 搜索只过滤左侧匹配项和祖先路径，不改变已展开的三维分支。清空搜索后恢复完整清单。
- WebGL 不可用时仍保留文字树与完整详情。图中展开动作不调用大模型，不代表某次真实工程任务的完成情况。

## 多 Agent 的展开顺序

1. **仓库与功能缺口分析**：仓库探索 Agent → 代码定位 Agent → 功能缺口分析 Agent，分别对应 explore-repository、ground-code、analyze-requirements。
2. **任务拆解与 Skill 分配**：任务图与交接契约、专业 Skill 路由、就绪优先级与文件归属。
3. **专业 Agent 协作实现**：网页与可视化（前端、JavaScript、Three.js）；后端与数据库（接口、数据库）；软件与集成（软件、集成）；嵌入式（MCU、MPU、协议），共十种专业。
4. **MCTS / UCT 候选空间树**：状态 → 选择 → 扩展 → 公开评估 → 反向回传 → 候选选择。
5. **诊断、补全与代码评审**：诊断 Agent、补全 Agent、评审 Agent，分别说明输入、职责、Skill 和真实代码位置。
6. **集成交接与再次修改**：版本与补丁整合、交接自动化测试、公开反馈再分配。

这六项是阅读顺序，不能解释为所有角色依次运行一次。主控先规划，核心分析与公开测试准备完成后进入修复；启用搜索时，每次扩展会重新规划并调用专业员工，深层扩展还会诊断。未启用搜索时直接走线性员工修复。选定候选后仍需公开复核、代码评审、独立验收与交付。

例如：**多 Agent → 专业协作 → 网页与可视化 → Three.js 场景 Agent**。整棵分支第一次点击即全部显示；继续点击仅查看具体职责。搜索具体 Skill 时保留匹配项及完整祖先路径。

## MCTS 依据现有代码拆分

对应 `testfix/repair_search.py` 的 `search_forest` 与 `testfix/search_workflow.py` 的 `run_repair_forest`。页面解释现有算法，不重新实现搜索器，也不把模型动画当作运行成绩。

| 步骤 | 代码行为 |
| --- | --- |
| 01 状态与根 | 初始工程、公开失败反馈、树编号、父节点、深度、visits、value_sum、mean_value |
| 02 UCT 选择 | mean_value + c × sqrt(ln(parent_visits + 1) / visits)；未访问节点优先，排除终止及深度上限节点 |
| 03 扩展 | fork 隔离候选，主控重新规划并执行员工任务图；可继续展开工作区、工具循环与结果复用 |
| 04 公开评估 | 冻结的相同测试身份；回归保留的合格候选奖励为 0.25 + 0.75 × 生成测试通过比例，否则为 0 |
| 05 回传 | 沿 parent_id 更新 visits、value_sum、mean_value，返回下一轮 UCT 选择 |
| 06 选择与提升 | 满足停止条件后，按公开通过、奖励、同哈希票数、较浅深度、较早迭代排序；保留来源再提升候选 |

01 初始化一次，02–05 循环，06 在停止后执行。当前实现每轮只扩展一个选中分支，员工模型可在分支内并发。多树策略为 minimal_change、interface_contracts、boundary_and_recovery；单树 / 多树、宽度和深度等以运行配置为准。

**独立验收不进入奖励、反馈或模型上下文。** 页面中的“空间”指候选代码与工程状态空间；不表示三维物理空间规划，也不宣称复现论文成绩或已证明任务分配性能提升。

## 实现

`web/explorer/details.mjs` 定义深层角色、职责、算法步骤、公式和实现映射；`parts.mjs` 构造层级、唯一归属、路径、搜索与显示范围。`framework.mjs` 定义有向关系、代码映射和完整标注布局计算；`explorer.js` 负责 Three.js 渲染、标注连线与交互；`framework.css` 定义展开后的卡片样式。所有元素由代码生成，使用仓库已有的 Three.js，不依赖 CDN 或外部模型文件。

主控内的 CP-SAT、出度 / 关键路径排序与 UCT 搜索是不同职责，归入主控不改变各自算法。WCTP 图执行在自动化测试中展示，也被员工协作复用；这不表示已完整迁入 WCTP 所有功能。MCU / MPU 等专业 Skill 已有定义，但通用固件构建、烧录及板级执行仍需实际工具链和适配器。未使用的专业按不适用记录，缺少执行能力时按阻塞记录。

本次调整是架构模型、归属和交互梳理，没有新增大模型实验成绩或改变实际执行算法。真实运行、验收结果与 AgentArts 连接状态仍以工程记录为准。
