# 自然语言需求与总控 Agent 协作

公开版保留控制器实现、请求样例与注册 fixture，历史运行产物和原始模型 captures 不随仓库分发。动态员工执行需要另行取得授权的外部 WCTP 源码；不具备该依赖时应使用不带协作请求的九能力入口。

`complete-project` 可以接收用户描述，并在已注册工程的验收合同内组织 Agent 协作。总控先分析功能、拆解工作项并指定员工 Agent；员工通过受控工具读取信息、提交修改和运行公开检查；总控再汇总实际结果，遇到失败或评审意见时调整任务并重新分配。最终是否交付仍由冻结测试、回归、构建和实际运行结果决定。

这里的 Agent 指调用大模型、受 Skill 约束、根据工具返回继续决策的执行角色。`codex_cli` 是当前默认模型传输，沿用本机已有登录态和请求模型 `gpt-5.6-sol`；它不是把宿主机文件系统和命令执行权直接交给模型。另有 `openai`、`ollama`、`agentarts` 传输，是否配置可用与是否已经真实运行需要分别记录。

## 命令行输入

先确认工程已经注册。当前内置 Flaskr 的 ID 为 `Project/flaskr`；执行 `scripts/register_richcli.py` 后，Rich-CLI 注册信息位于 `data/projects/registered/rich-cli.json`，准确 ID 为 `Project/rich-cli`。其他安装环境应读取各注册 JSON 的 `id`，不能根据文件夹名猜测 ID。

在源码根目录运行：

```powershell
.venv/Scripts/python.exe -X utf8 -m testfix.cli complete-project --project Project/rich-cli --request "修复 CSV 和 TSV 中的方括号丢失及异常退出，覆盖导出，并保留 --print 的样式行为。" --provider codex_cli --model gpt-5.6-sol
```

较长描述可保存为 UTF-8 文件，再传入文件路径：

```powershell
.venv/Scripts/python.exe -X utf8 -m testfix.cli complete-project --project Project/rich-cli --request-file request.txt --provider codex_cli --model gpt-5.6-sol
```

`--request` 与 `--request-file` 互斥。描述必须包含非空内容，原始长度不得超过 20000 个字符。文件只读，不会被改写；读取失败、非 UTF-8、空白内容和超长输入会在开始执行前拒绝。文件内容作为 `collaboration_request` 进入同一运行记录。未提供描述时保留原有完整工程入口。

提供描述的协作模式默认声明 7200 秒总墙钟预算，给额外规划、工具循环和重新分配保留额度；可用 `--wall-seconds` 显式覆盖。7200 秒是执行上限，既不是预计耗时，也不保证在限额内必能完成。未提供描述时仍使用原有适配器默认值。token、单次模型调用、每个员工步骤和业务修复轮数也各有界限，不能通过增加工作项绕过预算。

也可向本机服务的 `POST /api/project-runs` 提交 JSON，无需网页：

```json
{"project_id":"Project/rich-cli","provider":"codex_cli","model":"gpt-5.6-sol","collaboration_request":"修复 CSV/TSV 字面量与导出，保留原有行为并验证构建产物。"}
```

请求中的 `collaboration_request` 与 CLI 使用同一控制器，支持相同的非空和长度检查。没有显式设置墙钟时限时，协作请求默认 7200 秒。服务当前绑定本机地址；该接口存在不代表已部署到华为云。

## 总控与员工如何配合

总控使用规划 Skill 将描述映射到公开需求 ID，生成带依赖关系的工作项。每项工作至少要能说明目标、对应需求、执行角色、所需证据和允许修改范围。总控只能调度工程已支持的角色和工具，不能通过自然语言扩大文件权限、修改验收标准或取消交付检查。

| 角色 | 工作与证据 |
| --- | --- |
| 总控 / 规划 | 判断需求是否在合同范围内，分配探索和修复工作，读取员工结果，记录后续调整 |
| 探索 / 定位 | 根据模型决策选择查询、列举或读取公开源码，把工具观察交回模型后继续定位 |
| 修复 | 读取上游工作产物和真实失败信息，提出绑定当前候选哈希的补丁，由宿主校验和写入 |
| 测试 | 保留既有测试生成职责，输出步骤及需求覆盖关系，测试由宿主冻结后执行 |
| 评审 | 针对当前候选和实际公开测试结果独立评审，旧候选的批准不能用于新版本 |
| 验证 | 由确定性宿主执行独立验收、回归、wheel 构建和适配器规定的真实运行检查 |

动态工作图补充原有九项能力。九项能力仍承担需求分析、测试、诊断、评审和验收等必要检查；动态工作项可以根据本次功能范围安排不同的探索或修复职责。不能把固定调用八次模型解释为八个可自主协作的员工，也不能把规划 JSON 本身视为完成工程。

工具循环的判断依据是实际观察：模型提出允许的动作，宿主执行动作并返回结果，模型据此选择下一动作或结束。运行中保存任务依赖、上下游产物和协作消息，使后续员工知道前序 Agent 具体查到了什么、改了什么、检查结果是什么。没有运行的测试不得写为通过，推测不得写成工具证据。

当前员工动作包括 `read_file`、`search`、`run_public_tests`、`apply_patch` 和 `finish`。探索员工只在分配的公开文件中读取、搜索并汇报；修复员工先读取实际代码，再请求公开测试或提交补丁。宿主将每步动作与观察记录到 `artifacts/<run-id>/team/round-<轮次>/<任务ID>-step-<步骤>.json`，保留候选前后哈希；下游工作项接收上游交接结果。`apply_patch` 完成一次实施交接，后续是否通过测试与评审仍需实际验证。

发生公开测试失败或评审拒绝后，总控汇总本轮实际结果，保留上一版分配记录，再生成下一版工作项。重新分配继续使用原需求合同和冻结测试；它可以改变由谁处理、先处理哪里及修复方式，不能通过删除需求或放宽断言消除失败。预算和调用次数同时约束这些调整，预算耗尽时保留失败及尚未完成的工作。

当前员工模型决策通过真实 WCTP 图执行器并行运行，协作 CLI/API 默认提供两个模型槽位；可显式设置 `--model-slots` 或请求的 `budget.model_slots`。总控先确认实际前驱交接已完成，再按出度、声明关键路径、去重后继数量与任务 ID 的顺序派工。每个模型批次完成后，宿主依次处理工具和提交。相同文件的修复员工互斥；不同文件的补丁在核对推理基线及分配文件读集后可受控重基合并。实际并发时间段和源文件哈希记录在每轮 `batches` 中。这里采用批次屏障，不是抢占式或逐事件无屏障调度；并发收益需要单独对照实验。

WCTP 以固定源码依赖接入，默认引用同级目录 `../自动化框架/wctp`；其他机器通过 `TESTFIX_WCTP_ROOT` 指向源码根目录。仅加载经过 SHA-256 校验的 7 个图执行依赖文件，不加载设备或 GUI。实际执行的是原 `GraphExecutor.execute`，适配层限制批次宽度、搬移绝对导入到私有命名空间，并省略仅用于类型注解的设备环境导入。缺失或哈希不匹配时明确失败，没有模拟回退。源码版本升级需要审查并更新固定哈希。具体机制、配置和证据见 [WCTP 并行与出度优先](wctp-parallel.md)。

## Skill、权限与验收边界

Skill 文件和机器可读合同约束每个角色的输入、输出、依赖、可读写资源与预算。宿主还会检查文件路径、当前源码版本、冻结输入及产物哈希。模型输出是数据：只有宿主补丁工具可以在 `allowed_changes` 内写业务代码；员工不能修改原工程回归、冻结生成测试、独立验收或评测器，也不能提交任意 shell 命令作为工具执行。

探索工具仅暴露本次公开源码和有界观察，不提供密钥、模型配置中的原始秘密值或独立验收源码。Skill 权限声明和路径校验不等于操作系统沙箱；执行任意不可信仓库仍需要隔离执行环境。

当前完整工程适配范围是已注册的 Flaskr 和 Python package 工程。一个任意 GitHub URL 或一句新需求，并不会自动具备环境、依赖、回归、允许修改范围及独立验收。注册新工程需先固定源码版本和执行配置，再建立与需求对应的公开合同及受保护验收。

例如，Rich-CLI 合同覆盖 CSV/TSV 字面量、输入方式、导出及原有行为保持；描述“增加用户登录和云端同步”超出这个合同。系统应报告这部分不可执行或未被验收覆盖，不能执行旧套件后宣称新增功能全部满足。新增功能必须先补独立验收合同，才能作为完整交付的判据。

模型判断“需求匹配”也是待审查产物。现有验收能够检查已注册行为，不能证明它覆盖用户描述中的所有歧义或隐含功能。最终报告应同时展示需求映射、未匹配部分和实际执行结果；“测试通过”的结论限定在已检查的需求及输入范围内。

## 检查结果如何解释

每次新的执行使用独立 run-id，保存原需求、规划版本、工作项结果、模型轨迹、工具观察、补丁及最终报告。使用 `artifacts/<run-id>/report.json` 和对应测试、构建、真实运行记录评判实际完成度。CLI 参数测试与模型注入 fixture 只证明工程边界，不是一次真实大模型实验的成绩。

华为云 AgentArts 部署是另一项交付工作。本机 Codex 登录、上述协作代码和本地通过记录均不构成云端部署成功；不应把本机 OAuth 凭据打包到云镜像。参赛版本仍需在实际 AgentArts 环境运行并保留可复现的云端调用与执行证据。
