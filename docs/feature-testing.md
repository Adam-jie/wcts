# 描述功能，让 Agent 生成步骤并自动测试

在桌面软件打开“工程协作”，选择已导入的工程，再点击左侧“自动化测试”。

## 逐操作连线测试

对于已登记的 TaskBoard 工程，可以选择“逐操作连线测试”。Agent 根据描述拆分功能条件并生成操作计划；每个步骤包含名称、HTTP 方法、接口路径、输入、预期状态码、响应断言和可传递的变量。`RESTART` 步骤会重启应用并继续使用本轮数据库。审核区支持修改步骤次序、请求和断言，确认后由原 WCTP 顺序执行。图中的节点可点击查看实际请求、响应和检查结果，也可以切换循环轮次。原有“测试文件执行”方式仍然可选。

该模式当前只支持 TaskBoard 的本地 HTTP API，测试的是接口与数据库行为，不是浏览器鼠标操作或硬件实测。节点图用于查看真实执行，步骤编辑通过表单完成，尚不支持在图中拖拽修改连线。导出的 WCTP 图需要本项目提供的动作绑定才能执行；人工编辑后的计划不替代独立验收。

## 测试文件执行

1. 在“要测试的功能与预期结果”写出行为。例如：中文搜索只显示匹配标题，无结果时为空；每页两条，相邻页不重复；完成及取消状态在重新打开数据库后保持。
2. 选择“原始工程”或该项目已通过验收的补全版本。选择上方已配置的真实模型和循环轮数。
3. 默认勾选“先生成测试步骤，检查或修改后再执行”。系统先分析功能条件，再生成测试文件和多组数据，进行结构校验和生成前置校核；校核只基于公开源码和需求，发现具体错误时总共最多生成三次。生成后显示“等待确认测试计划”，此时没有执行测试。
4. 展开“检查或修改测试计划”，检查或修改后点击“确认计划并运行”。也可取消勾选先检查，直接生成并执行。实际执行时交给原 WCTP 图执行器，按顺序执行原有回归和每个功能步骤；可点击连线节点、切换轮次查看逐条实际结果。
5. “自动测试记录”保留不同描述的任务；刷新页面后可继续跟踪活动任务或查看结果。“查看生成的功能条件、步骤与测试代码”显示真实模型输出。
6. 已生成测试计划后，也可随时展开编辑区，修改步骤顺序、名称、预期说明和测试代码；高级 JSON 编辑可调整完整计划与覆盖关系。保存会创建一条新运行，不修改原记录，也不重新调用模型。当前可以上下调整步骤顺序，尚没有图形拖拽连线编辑。

预期说明只是文本，实际判断来自测试代码中的断言；修改预期时应同时检查和修改测试代码。人工编辑后的测试不会替代独立验收，重新运行仍会校验计划、工程版本和步骤覆盖并执行原有回归。

## 执行与判定

- 本入口只生成和执行测试，不修改产品源码或此前验收记录。新建带哈希校验的独立工程副本；对补全版本测试时，生成全新的测试，不借用旧生成测试冒充新结果。
- 原 WCTP 的 `StepRegistry`、`Step.execute`、`LoopStep`、`GraphExecutor.execute` 执行真实 YAML/连线图。功能步骤采用原生顺序边，避免多个测试进程争抢资源，也避免排队等待消耗步骤超时。
- 每个步骤绑定一个校验后的 `test_*.py` 文件。固定宿主工具调用受限子进程运行 pytest，记录 JUnit、导入源码绑定、命令与日志；模型不决定任意 shell 命令。
- 测试步骤和覆盖关系必须引用实际生成的测试文件与函数。所有用户功能条件必须有映射；测试模块需含断言。覆盖映射和模型校核不等于数学证明或穷尽验证。
- 每轮使用独立临时目录/数据库。后续轮次收集的用例身份必须与首轮一致。断言失败或执行异常均不能显示为通过；失败会停止后续步骤/轮次，并保留已执行回执。
- 测试首次创建数据库时也应处理程序自身的种子数据。生成前置校核不读取独立验收，不在执行后降低断言来迁就结果。
- 目前此入口复用已登记的 Flaskr、Python 应用和 Python CLI 包适配器。TaskBoard 的 WSGI/Storage 测试是接口和数据库行为验证；不把它写成真实浏览器操作或云端部署证据。

使用的应用内 Skill 位于 `testfix/feature_skills/feature-testing/SKILL.md`，记录其 SHA-256。模型服务沿用项目配置；CLI 请求型号与服务实际返回型号分别记录，服务未报告时实际型号为空。
