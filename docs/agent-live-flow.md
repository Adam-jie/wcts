# 实时三维协作过程

当前版本按 CodeAgent 主控、多 Agent 生成与补全、自动化测试分层；主控算法、员工实例、流程能力与执行底座分别呈现。联合分配、任务图与本轮真实实验见 [工程架构](completion-architecture.md)。

桌面“工程协作”在功能需求后展示三维协作工作区。开始补全后自动滚动到这里；本进程启动的工程运行在主控发布检查点时通过事件流推送更新，不增加模型调用。由其他进程执行的任务每 1.6 秒读取持久化快照，不能保证显示快照间的每个中间状态。CodeAgent 和实际员工以三维工位呈现，其他流程能力和执行底座分别显示。右侧列出任务分工、各任务状态和最近进展，可点击查看文件范围与交接内容；尚未派工的任务明确标为计划。

亮线、方向箭头和一次移动光点对应收到的执行事件；处理中的节点持续轻微浮动。计划依赖用灰线标明“经主控”，不会把计划当作已经发生的直接通信。员工完成代表交接，测试结论仍以原有回归、生成测试、独立验收和运行检查为准。

可拖动旋转、滚轮缩放、复位、展开视图，点击三维节点或右侧按钮查看详情。已结束的任务默认显示最终记录，点击“回放本次过程”按事件顺序播放；支持暂停、拖动进度和 1/2/4 倍速。回放压缩了事件之间的等待时间，时间标签仍显示原始记录时间。运行中的任务也可回看，点击“回到实时”恢复跟随。连接失败时保留最后记录、停止活动动画并自动重连；WebGL 不可用时仍能通过文本节点查看记录。模型内部生成文本并不会逐字推送，界面只展示宿主已经记录的阶段、工具和交接事件。

前端实现是 `web/implementation/flow-model.mjs`、`run-flow.js` 和现有页面。使用本地 Three.js r170 和 Gobkit 办公人物模型，运行时不依赖外网或 CDN；素材来源和授权见 `web/implementation/vendor/models/README.md`。角色外观基于已收到的派工角色选择，未派工时使用通用形象。人物动作是状态的可视化表达，不代表逐字记录了模型的内部动作。新员工事件附带任务 ID、轮次、发送者、接收者和操作结果；老记录按精确派工标题和工具任务 ID 对齐。历史数据不足时只显示已知事件与计划，不补造实际交接。

早期平铺版本验证包括 10 项事件投影单测、36 项相关 Python 检查；当前分层版本包含 13 项投影单测、相关后端与浏览器检查。早期版本的验证记录保留：，以及浏览器中的真实 TaskBoard 历史回放、旋转缩放、员工详情、并行状态、暂停和窄屏检查。实时追加、重复快照、断线恢复使用明确的受控快照测试；这不是一次新的 LLM 工程实验。证据在 `artifacts/agent-flow-check/validation.json` 与同目录截图。浏览器检查没有提交任何模型任务。

复现：先启动本地应用后端，以 `TESTFIX_UI_BASE` 指定普通本地测试服务（默认 `http://127.0.0.1:2890`），通过 `TESTFIX_PLAYWRIGHT` 指定 Playwright 安装路径，再运行 `node scripts/verify-agent-flow.cjs`。不需要读取桌面会话认证信息。
