# 华为 ICT 大赛创新赛赛题一：参赛方案与材料草稿

更新：2026-10-31。本文是项目准备材料，不代表报名系统已经改选，也不代表通过资格审核。

## 赛题与作品定位

- 赛题：基于华为云产品打造 AI 创新应用。
- 作品名称：无遁 Fix Agent：面向工程的多智能体协同开发补全与自动化测试平台。
- 应用领域：软件工程、嵌入式工程与自动化测试。
- 目标用户：需要开发、修改或补全工程，并验证需求的开发与测试人员。
- 要解决的问题：工程需求可能含有歧义，修改涉及多个关联模块，功能完成后仍需测试和确认原有行为。
- 作品主线：提供需求或工程 → 澄清必要信息 → 总控分析与约束分工 → 多 Agent 开发、修改或补全 → 可调整的测试计划与 WCTP 执行 → 展示差异、运行过程和报告。
- 实际能力范围：已验证特定 Python 工程的修改与测试；通用新项目开发、任意仓库、实物硬件和仪器测试不因设计目标而视为已完成。

本届高校通知列明创新赛报名时从三个赛题中选择一个：[大连理工大学通知](https://chuangxin.dlut.edu.cn/info/1020/16867.htm)。公开的[赛题一介绍](https://www.10100.com/article/152896034)提到使用 CodeArts、华为云服务及云端部署，但它是转载资料。确切强制项、提交清单、组队规则和评分标准应以[官方赛事页面](https://e.huawei.com/cn/talent/#/ict/innovation-details?zoneCode=027425&zoneId=98269700&compId=85132021&divisionName=%E4%B8%AD%E5%9B%BD%E5%8C%BA&type=C002)及组委会附件为准；目前无法从该动态页面完整读取细则。

## 报名表文字草稿

### 方案背景和价值（500 字以内）

在软件维护过程中，开发人员需要对照需求查找缺失功能，修改已有代码，并反复确认新功能和原有功能是否正常。需求、代码与测试证据分散，会增加定位和验证成本。

无遁 TestFix Agent 面向已有软件工程的功能补全与测试场景。用户导入支持的项目并描述问题或目标功能后，系统组织多智能体分析需求、分配任务、生成候选修改，并根据功能描述生成测试步骤，通过自动化测试执行和独立验收展示修改结果。作品旨在让开发人员同时看到代码改动、测试过程和运行证据，辅助理解软件是否满足给定需求。

### 华为云产品的计划使用（1000 字以内）

作品计划使用华为云码道 CodeArts 代码智能体辅助项目开发、测试和部署，记录需求分析、代码修改、测试与问题处理过程；在华为云上部署应用和演示入口，根据实际业务需求选择云资源，形成可访问、可复现的演示。CodeArts 的实际操作记录、云资源配置和在线运行情况将作为作品证据。

系统自身的 CodeAgent 主控负责结合需求、依赖和资源条件组织任务；专业 Agent 按各自职责分析和修改代码，测试模块根据功能描述生成测试步骤并交由 WCTP 执行。完成后展示代码差异、测试回执和独立验收结果。

截至本稿更新，本机已完成任务管理系统示例的补全和自动化测试验证；CodeArts 实际开发使用、华为云应用部署和线上端到端验证尚未完成。以上云端内容为实施计划，完成并取得证据后才能改写为实际成果。

### 整体技术方案

```text
用户提供源码与功能描述
          ↓
应用入口与任务管理
          ↓
CodeAgent 总控：需求分析、依赖与资源约束、任务分配
          ↓
专业 Agent：工程分析 → 代码修改 → 评审及反馈
          ↓
功能测试生成 → WCTP 步骤与循环执行 → 原有回归和独立验收
          ↓
修改差异、运行日志、可视化过程与验证报告

开发侧：CodeArts 辅助开发与部署（待实际使用）
运行侧：华为云应用部署及必要云服务（待选择、部署和验证）
```

CodeArts 辅助开发本作品，与作品内部的 CodeAgent 主控是两个不同角色。AgentArts 相关适配保留；如实际采用，再说明它处理哪些调用并提供运行证据，不预先声称已部署。

### 关键模块

1. **CodeAgent 主控与约束分工**：整理需求与任务依赖，使用现有整数约束求解器选择和调度任务；实际分工与反馈以运行记录为准。
2. **多 Agent 功能补全**：根据支持的工程适配器分配分析、实现和评审任务，保留候选代码、补丁和交接记录。当前不能承诺支持任意源码或安装包。
3. **自动化测试**：根据功能描述生成并校核测试步骤，调用原 WCTP 核心执行器的步骤、图和循环能力；执行原有回归与独立验收，展示真实记录。完整 WCTP 设备驱动和硬件实测尚未覆盖。
4. **可视化与交付**：桌面工作台展示任务状态、协作过程、测试与代码差异；华为云在线演示属于待实施工作。

### 方案效果与证据

2026-10-31，在隔离的任务管理系统示例上实际运行：补全后的模型生成测试 4/4、原有回归 6/6、独立验收 12/12、实际运行检查 37/37。另对补全版本根据功能描述生成测试，由 WCTP 执行两轮，累计 22/22 次用例执行通过。工程完整回归为 1228 通过、3 跳过。

这些数字分别来自不同测试集和执行轮次，不是修复任务数量、通用成功率、成本下降比例或云端成绩。示例属于开发验证案例，不能当作未见过的独立基准；报告见 [本地验证记录](contest-local-verification-20261031.md)。
