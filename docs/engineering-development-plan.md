# 无遁 Fix Agent：工程开发、修改、补全与测试

## 产品流程

用户可以从新功能描述或现有工程开始。系统整理需求并提出必要的澄清问题；CodeAgent 主控基于工程信息、任务依赖和资源条件安排专业 Agent；开发、修改或补全后的工程进入 WCTP 测试，用户检查测试计划并可修改，实际执行后生成报告。

三类任务使用同一主控和测试入口，但需要不同的工程合同：

- 开发：从已确认需求、目标环境与验收条件出发，生成和集成功能。
- 修改：读取现有工程，定位修改位置及相关模块，在副本中修改并验证原有行为。
- 补全：结合工程说明、实际故障和测试反馈修复缺失或错误，实现已确认的行为。

## 已接入的部分

- 任务资料支持真实模型生成草稿、列出问题、回答后基于上轮草稿继续分析；用户采用并保存后才写入任务资料。它仍不是对任意项目自动生成可运行工程。
- 已注册的 Python 工程可以使用主控、多 Agent、整数约束分配及独立验收；不同类型工程需要自己的执行适配器。
- 描述功能后可生成测试计划。默认先等待用户检查，可编辑步骤顺序、名称、预期说明、测试代码和高级 JSON，再创建新记录交给 WCTP 执行；原结果保留。也可取消等待，直接生成并运行。
- 测试计划包含顺序连线预览；真实 WCTP 执行后显示运行图与回执。目前没有图形拖拽创建连线。
- 原 WCTP 核心图执行文件作为外部源码依赖加载；设备驱动和 PyQt 界面未整体集成。

用户修改预期说明不会自动修改测试代码断言，必须同步检查代码。人工编辑的测试不等于独立验收；结果只表示实际执行的断言是否通过。

## 仍需实施与验证

1. 通用工程识别与执行适配：当前自动注册仍针对特定工程结构；需要逐步增加受支持的工程类型，固定环境、运行方式与验收合同。
2. 工程开发：从零生成工程并真实构建、运行、验收的通用链路尚未完成。
3. 澄清与执行交接：当前澄清发生在任务资料阶段，主控执行中发现新的问题后暂停、向用户追问并恢复同一运行仍需接通。
4. 测试编排：目前使用步骤表单和高级 JSON 调整测试，图形拖拽连线和通用硬件步骤接入尚未完成。
5. 华为云：CodeArts 实际开发使用、云端部署和端到端演示尚无完成证据。
6. 硬件：现有 HTTP、SSH、串口能力见 `hardware-testing.md`；连接真实 MCU/MPU、示波器和频谱仪需要明确型号、通信协议及测试合同，并分别留存真实测量回执。

## 本轮验证

真实模型对个人任务管理需求提出关键问题，用户回答不需要登录和本地 SQLite 后重新生成草稿。测试计划在用户确认前暂停，随后通过界面调整步骤及顺序并启动两轮 WCTP 测试，28/28 次用例执行通过；完整结果与运行 ID 见 `feature-testing.md`。该验证使用隔离的 Python 任务管理示例，不代表全部软件工程或硬件已验证。

本轮后端全量回归为 1237 项通过、3 项跳过，结果保存在 `artifacts/project-direction-final-pytest.xml`。桌面启动、引擎握手和恢复等检查 11 项通过；这些回归检查不等于更多真实项目或硬件实验。
