## 实际采用的原框架

原依赖为用户提供的 WCTP，默认位置 `../自动化框架/wctp`，也可通过 `TESTFIX_WCTP_ROOT` 指定。七个执行核心文件逐字节与原始 `wctp.zip` 的 SHA-256 一致，证据见 `artifacts/wctp-product-check/wctp-source-binding.json`。没有复制或替换其算法。

软件测试真正调用原 WCTP 的 `parse_graph`、`validate_graph`、`StepRegistry`、原生 `Step.execute`、`LoopStep`、`ExecutionContext`、`GraphExecutor.execute`。仍使用已有私有导入命名空间适配；仅省略类型注解依赖的设备环境导入。原设备驱动和 PyQt 界面没有整体复制到 TestFix；这里是在桌面工作台中显示同一执行图及其真实回执。

WCTP 负责步骤与图执行；pytest、构建、HTTP、数据库重启检查是固定注册的宿主动作。它们继续在受限、带超时的子进程中执行。原 WCTP 的线程超时本身不能强制中断 Python 回调，因此不把它当作操作系统沙箱。

新工程运行自动形成原版公开测试、候选公开测试、最终独立验收等 WCTP 用例。图和结果位于 `artifacts/<run-id>/tool_calls/<call>/wctp/`。分叉分支使用不同输出变量、测试数据目录和进程；循环失败后停止，保留已完成回执。循环的 False 是正常退出，不是业务失败。

导出的 YAML 包含图、控制步骤和 `required_host_steps`。业务动作必须由 TestFix 按冻结输入绑定。直接导入没有宿主动作注册的原 WCTP 会拒绝未注册步骤，不能把无动作的默认成功当成真实测试。

## 验收与状态约束

- 原源码、冻结模型测试、独立验收和候选版本在重测前后核对哈希。
- 每轮生成测试、原有回归及独立验收的用例身份必须与来源验收一致；独立验收的前后用例也必须相同。不能因少收集用例而显示通过。
- 原版缺口对照预期出现可执行的功能断言失败；收集错误、超时和依赖错误不算发现功能缺口。表格仍显示原始逐用例状态。
- 中断所属任务后，未完成用例显示中断或失败；保留原始记录，不补写完成证据。
- 切换项目后，旧请求的响应不能污染新项目。重开页面能恢复活动重测；临时读取错误保留记录并重试，期间禁止重复提交。
- 三维标签缓存实际尺寸，不再因隐藏后的零宽度反复显隐。轮询保留未改变的侧栏节点和展开状态。
