# WCTP 实际引用、并行员工与出度优先

公开版说明：本文保留已完成本地实验的文字摘要。原始运行目录、模型输入输出、机器路径和审计脚本不随公开仓库分发；重跑会在本机生成新的证据。WCTP 原源码同样不分发，需运行者另外取得授权并配置 `TESTFIX_WCTP_ROOT`，见根目录 `THIRD_PARTY_NOTICES.md`。

本次改动使用原 WCTP 的图执行器作为员工模型动作的实际执行后端，保留 TestFix 的需求合同、Skill、补丁边界和独立验收。此前串行运行的报告仍作为历史记录保存，不改记为并行成绩。

## 依赖接入

源码位于同级 `../自动化框架/wctp` 时自动发现。其他位置配置 `TESTFIX_WCTP_ROOT`，其值为包含 `src/engine/graph_executor.py` 的 WCTP 根目录。需要原源码；当前 TestFix 源码包不复制原 WCTP。PyYAML 已纳入主工程依赖与 `uv.lock`。

加载范围固定为原 `graph_executor.py`、`context.py`、`case_parser.py`、`step_registry.py`、`config.py`、`exceptions.py`、`logkit.py`，逐文件核对源码 SHA-256。加载器使用私有命名空间，绝对 `src` 导入在内存中重定位；仅用于延迟类型注解的 `EnvBlueprint` 导入被省略，以避免设备驱动依赖。原图执行、分支取消、汇聚和循环逻辑没有复制或改写。适配子类按线程上限拆分就绪批次；每个已启动子批次全部完成后才处理结果，发现异常时不再启动后续排队子批次。

原源码缺失或发生变化会明确失败；不会自动改用另一个执行器。本机路径不是云端部署配置。构建华为云环境时需提供同一版本的 WCTP 依赖并设置该变量。

## 实际调度

1. 验证任务图的需求覆盖、合法路径和无环依赖。
2. CP-SAT 约束依赖、模型槽位、声明时间与 Token，以及共享文件的修复冲突；不相交文件允许规划重叠。
3. 根据已完成的真实交接形成就绪集合，不仅查看初始入度。
4. 按以下字典序派工：直接出度降序 → 声明关键路径降序 → 去重后继数降序 → ID 升序。出度不能越过依赖或资源限制。
5. 将可执行员工的下一次模型决策作为 WCTP 分叉／汇聚批次实际运行。每员工仍保留自己的工具观察和上游交接。
6. 模型批次完成后由宿主提交工具动作。同文件修复员工整个工作项互斥，不同文件的候选补丁检查读集后可受控重基，禁止用重基掩盖过期模型提案。
7. 失败测试、拒审和验收摘要交回总控，下一轮重新分解和分配；最终验收规则不变。

这实现并行模型决策与宿主协调提交。WCTP 和调度器使用批次屏障，工具与代码提交仍顺序处理；没有声称任意时刻的抢占式调度、并行构建测试或实际耗时全局最优。

## 并发预算与证据

模型传输为每次调用分配独立 ID、线程局部 trace 和唯一产物目录。仅记录与落盘加锁，网络／CLI 调用不被该锁串行化。总控在调用前将所有在途预留计入总 Token 额度，结束后按对应调用的服务报告核算，异常也释放或结算预留。CLI 上限仍是预留与调用后核算，不是服务端硬 Token 上限。

每轮 `batches` 保留 WCTP 引用文件哈希、实际动作开始结束时间、线程名和峰值并发；`dispatches` 记录就绪候选、优先顺序与实际启动任务；`schedule.graph_metrics` 给出入度、出度、声明关键路径和后继数。补丁回执额外记录推理基线、提交基线、读集前提及是否重基。旧步骤回执在下一批提交前和交付前复核，变化后停止。

## 无需网页的运行入口

```powershell
.venv/Scripts/python.exe -X utf8 -m testfix.cli complete-project --project Project/rich-cli --request-file examples/rich-cli-parallel-request.txt --provider codex_cli --model gpt-5.6-sol --model-slots 2 --wall-seconds 7200 --token-limit 1000000
```

请求模型配置沿用已有登录；服务未回报实际型号时仍如实记录。该命令会发起新模型调用。CLI/API 在协作请求未指定槽位时默认为 2，普通非协作入口保持原默认值。直接调用底层 Python `execute_project_run` 时需显式传入并行预算；省略预算仍使用通用默认 1。设为 1 是资源配置，不是旧版强制串行。
