## 让评委实际看到什么

下面是本项目的验收主线，不冒充官方评分权重：给出真实需求和原版工程，复现失败，让 Agent 读取信息、分工、修改，最后让独立程序验证交付物是否能够运行、需求是否实现、旧功能是否保留。3D 图负责让派工、依赖和反馈更容易看懂；通过与否由实际运行的结果决定。

| 演示问题 | 应当打开的证据 | 不能替代该证据的内容 |
| --- | --- | --- |
| 需求和故障来自哪里 | GitHub 项目、固定 commit、issue/需求原文、许可、原版失败命令 | 一段虚构需求或人为注入故障却称真实 issue |
| 总控怎样安排员工 | 当次任务图、就绪集合、入度/出度、约束、派工和交接记录 | 一张固定动画图 |
| LLM 做了什么 | 当次模型调用 ID、已脱敏输入输出、工具选择与宿主执行回执 | 只有一句“Agent 已完成” |
| 是否真正并行 | 各调用的开始/结束时间、交叠区间和 WCTP 元数据 | 两个同时闪烁的节点 |
| 修复了什么 | 绑定候选源码哈希的 patch.diff、修改范围与评审 | 仅展示代码生成文本 |
| 功能是否满足 | 事先冻结的独立验收前后结果、原有回归与日志 | 让补全 Agent 改写断言后的全绿 |
| 交付物能否运行 | 新环境安装/构建、真实 CLI 或 HTTP 业务输入输出 | 只检查语法或 import 成功 |
| 华为技术如何参与 | 真实 AgentArts 应用/会话/Trace、部署资源、CodeArts 使用记录 | ECS 上一个网页或本地 SDK 模拟请求 |

模型实际型号没有被服务返回时，界面只显示“请求型号”和证据级别。所有历史回放、合成调度演示、实时运行都应显著区分。没有日志的步骤显示“尚未执行”；不能根据时间轴动画补出成功事件。

## 建议的八分钟排练脚本

八分钟只是当前项目的排练预算，正式赛程下发后再调整。真实 LLM 任务可能超时；可以现场发起一条新任务，同时保留一条完整历史运行作备用。切换历史记录时必须明确显示历史 run-id，不能将录像或回放称为实时完成。

| 时间 | 操作 | 观众能检验的结果 |
| --- | --- | --- |
| 0:00–0:45 | 说明目标用户和问题；让测试者选择一个已注册任务或输入约束内的新需求 | 任务来源、commit、预期功能和允许修改范围明确 |
| 0:45–1:30 | 从干净原版运行同一复现输入 | 失败输出或缺失功能可见；环境错误另行标记 |
| 1:30–2:30 | 发起真实运行，打开总控图和任务合同 | 展示依赖、就绪任务、出度优先与资源/文件冲突限制 |
| 2:30–3:30 | 点开员工节点，查看读取、搜索、实际工具日志 | 模型决策与宿主执行对应，依赖未完成的员工仍等待 |
| 3:30–4:30 | 查看测试与诊断；若发生拒审/失败，展示反馈如何回到总控 | 第二轮分配须来自当次实际事件，不能预先伪造 |
| 4:30–5:30 | 查看补丁并说明必要修改；展示边界保护 | 修改文件、前后哈希和验收测试保护可核对 |
| 5:30–6:45 | 运行独立验收、原有回归、wheel/应用构建与业务操作 | 功能满足与原有行为保留分别报告；失败如实保留 |
| 6:45–7:30 | 打开实际华为平台链路和运行资源 | 部署完成后才展示；当前应标为“待部署” |
| 7:30–8:00 | 导出交付包和证据清单，展示多任务统计与失败样例 | 他人能用相同源码、输入和命令复现 |

现场操作员应保留整次未剪辑录屏；另做符合后续官方时长要求的精简视频。网页发生故障时，保留 CLI 入口和本地证据包继续演示，不以重新播放动画掩盖失败。

## 追加检查发现回归的真实记录

2026-10-15 的浏览器新实验 `66c779505ef340cb83a758ca8be8c340` 在原注册评测下通过：生成测试 11/11、独立验收 21/21、回归 14/14、构建 1/1、安装后 CLI 16/16。独立追加审查随后确认 R2 回归：普通 CSV 同时指定 `--head 1 --tail 1`，原版按 head 优先成功，候选增加互斥判断并报错。该运行现在应表述为**原冻结验收通过，追加兼容性检查失败**；原报告未被改写，追加结论单独绑定候选 SHA 保存和展示。

因此已建立 `behavior_regression_v2`，逐字保留原测试文件，新增九项真实 CLI 检查。原版 22/22 通过，66c 候选 19/22，通过六项零值用法错误检查，但在显式 CSV stdin、自动 CSV、自动 TSV 的三个双参数场景失败。新一轮将采用 23 项合并回归（上游 1 项、行为 22 项）和 25 项安装后 CLI 检查；旧版测试、封存清单和成绩保持不变。

这条回归由项目外的独立追加审查发现，后续另开真实运行，不能宣称原框架已经在同一业务轮内自动发现并修复。rich-cli 属于据此调整过的开发案例，不能再当作未见最终留出任务。演示应同时保留失败和修复结果，说明测试覆盖如何增加、哪些证据仍未取得。

后续真实运行 `165640a1a67e4eebbc42a2602be651fc` 已完成，用时 591.429 秒、16 次模型调用、提供方报告 Token 467124。生成测试 5/14 → 14/14、独立验收 3/21 → 21/21、合并回归 23/23、wheel 构建 1/1、安装后 CLI 25/25。独立从该 wheel 再执行三种输入模式的 head/tail 组合，均退出 0 且只显示首行；候选源码、评审、wheel、交付 ZIP 和工具回执的哈希已复核。

当次修复员工曾提交不允许的结束动作和非 Python 源码格式的补丁，宿主均拒绝，随后在同一员工动作循环内提交了有效源码。这是当次实际工具反馈纠正；它不等于第二轮总控业务重规划。补丁仍含较多格式改写与一处 notebook 文档字符串缩减，不能称最小补丁。上述结果只说明这一个开发任务通过当前冻结合同及追加场景，不是公开基准总体成功率。

## 数据集与实验登记建议

本项目需要的是“真实仓库 + 问题/需求 + 原版版本 + 验收”的任务集。函数题数据集可以做辅助单测，但不应代替完整工程的安装、接口/CLI、持久化和回归验证。

每条任务至少固定：任务 ID、上游仓库与许可、基线 commit、问题/需求来源、运行环境、安装命令、原版复现命令、可修改路径、独立验收版本、回归测试版本、业务操作命令、时间/Token 预算。参考补丁和独立测试不可进入修复 Agent 的上下文。不能把上游修复后的代码当作基线。

先建立小规模、可复现的完整工程任务组，再扩展公开基准。建议覆盖 CLI、Web/数据库应用、纯 Python 包三类，每类至少一个真实项目；数量是项目实验目标，不是已收集完成的声明。每个新项目先注册和验证执行适配器，尚未支持的仓库不能在界面显示“可立即运行”。原版依赖安装失败的任务记录为环境阻塞，不能算修复成功。

用同一批冻结任务比较单员工、并行员工、关闭出度排序、关闭指定 Skill 的方案；保持模型请求配置、预算、工具和独立测试相同。每方案建议重复至少三次，保留所有尝试、失败、超时与资源阻塞。通过率分母是事先登记的任务数；耗时和 Token 按任务分别记录，并报告重复运行的波动。只有取得配对实验后，才报告某策略的提升；一条成功案例不能证明算法优于其他系统。

## 每次运行收集的交付证据

1. `task-manifest.json`：来源、固定版本、许可、复现和验收命令。
2. 需求合同、任务图与总控每轮决策、员工交接和真实工具回执。
3. 脱敏模型调用记录：请求型号、服务实际返回型号或未知、调用 ID、开始/结束、Token 口径。
4. 原版和交付版测试原始输出、JUnit XML、候选源码绑定、冻结测试哈希。
5. 实际代码差异、评审结果、构建日志、全新环境业务运行结果。
6. 最终交付包及 SHA-256、可重放命令、所有失败尝试与限制说明。
7. 平台采用证据（部署后补）：AgentArts 应用与会话/Trace 对应关系、华为资源和运行截图、CodeArts 对话/开发操作记录。公开版本删除密钥、Cookie、联系信息和敏感资源配置。
8. 全流程未剪辑录屏与按本届正式要求制作的演示视频。

这份清单服务于可复现和答辩准备，不代表组委会已经确认的最终提交文件格式。
