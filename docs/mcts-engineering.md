# 可执行的 MCTS 多树工程补全

本实现参考 [SWE-Search（ICLR 2025）](https://proceedings.iclr.cc/paper_files/paper/2025/hash/a1e6783e4d739196cad3336f12d402bf-Abstract-Conference.html)、作者开源的 [moatless-tree-search](https://github.com/aorwall/moatless-tree-search)，以及 [Forest-of-Thought（ICML 2025）](https://proceedings.mlr.press/v267/bi25a.html) 与[官方代码](https://github.com/iamhankai/Forest-of-Thought)。没有复制论文的实验成绩，也不把 MCTS、UCT、多树或出度优先排序称作本项目原创算法。

这里的适配是：把候选状态变成可回溯的完整注册工程工作区，将总控与专业员工、Skill、WCTP 执行、公开测试反馈和既有交付关卡接到搜索节点上。与 SWE-Search 的 LLM 价值函数不同，本实现使用实测公开测试作为数值评价；与 FoT 的推理题不同，这里的节点对应真实文件和测试结果。因此不是两篇论文的逐项复现。

## 工作方式

1. 需求、仓库探索和实体定位先完成，再生成测试步骤、用例与需求覆盖映射。
2. 搜索模式在冻结测试前执行辅助解析器的标准 HTML 样例检查，并由新的一次模型调用审查测试语义。审查错误、解析器错误会反馈给测试生成器。未通过时不进入代码补全。此检查覆盖识别到的辅助接口，不能证明任意测试都正确。
3. 每棵树采用不同策略入口：最小修改、接口契约、边界与恢复。每轮只激活一个候选分支，该分支内的员工调用仍可由 WCTP 并行执行。
4. UCT 根据已有平均值与探索项选择树和可扩展节点。候选从父工作区复制，重新分配专业员工，必要时根据父候选的真实失败结果重新诊断。
5. 员工通过实际受限工具读取、搜索、提交补丁。相同文件互斥；宿主串行提交并核对读集。专业 Skill 文本不产生额外工具权限。
6. 冻结的生成测试和原有回归在分支内执行。只有回归保留且用例身份一致的候选才可选择；评价为 `0.25 + 0.75 × 生成测试通过比例`。不合格候选回传 0。该权重是可解释的工程规则，尚无实验支持它优于其它权重。
7. 用例位置包含工作区编号时，只在冻结测试哈希一致后替换明确的生成套件路径前缀；测试函数、参数、数量和顺序不变，原始 JUnit 另行保留。未知身份变化仍拒绝。
8. 同一候选源码哈希可复用已绑定的公开测试结果。访问次数、均值和评价沿父链回传，允许从失败候选继续修正。
9. 根据公开通过、评价和相同候选的支持次数选定一个分支，核验交接证据，再提升到交付工作区。只有这一个候选进行最终评审、独立验收、wheel 构建与真实 HTTP/CLI 检查。独立验收失败不会反馈到本次搜索中反复优化。

## 配置和运行

```powershell
uv run python -X utf8 -m testfix.cli complete-project --project Project/flaskr --provider codex_cli --model gpt-5.6-sol --search forest --search-trees 3 --search-iterations 9 --search-width 1 --search-depth 3 --search-min-successes 3 --test-quality-attempts 6 --wall-seconds 36000 --token-limit 4000000
```

`--search none` 使用原有线性流程，`--search mcts` 使用单树，`--search forest` 使用多树。树数、扩展次数、宽度、深度、成功候选数、全局时间和 Token 预算可配置。上界不能等同于实际费用：真实调用的 Token 以服务回报为准，CLI 未回报时保留未知/保守核算。停止条件防止失控执行，不以跳过验收换取成功。

每个员工的五步动作契约在搜索分支中独立核算；总调用和并发仍由全局预算核算。树数和深度的扩大不增加文件权限。当前任务图按注册工作包分工，通用多语言工程、目标数据库和固件构建仍需要相应适配器，缺失能力不会冒充已执行。

Flaskr 测试环境固定安装 BeautifulSoup 4.14.2，提示测试生成器使用成熟的 DOM 解析器，避免自行实现 HTMLParser 带来的错误。`--test-quality-attempts` 设置测试产物审核次数，每次审核和重生成都消耗实际预算。模型服务单次超时最多重试一次，保留失败调用及未知用量，重试仍须通过原调用额度与全局资源检查。

测试审核负责识别断言与实际夹具中的错误，不能声称穷尽测试或证明任意自然语言消息的意义。未覆盖情况写入审核摘要，最终独立验收和评审仍必须执行。每次重生成传递完整审核历史，避免“禁止固定文案”与“必须语义识别任意文案”等反馈反复切换。

若运行在测试审核阶段失败、尚未修复或执行独立验收，可在相同项目/模型/公开需求下增加 `--resume-public-run <失败运行ID>`。它在全新工作区复用五项公开产物，并重新审核最后一版测试；失败运行不会被改成成功，复用调用标为 `public_checkpoint_reuse`，不计新推理。不允许恢复已经产生补丁历史、候选测试结果、搜索分支或独立验收的失败运行，也不允许变更用户需求。这种调试恢复不是对照实验的已验收基础。

当前本机执行器采用已注册可信仓库与受约束的模型产物，并非恶意代码的操作系统沙箱。模型请求通过公开快照和受限工具排除独立验收源码，哈希保护检测文件修改；普通 Python 测试进程仍有宿主用户的文件读取能力，不能据此宣称抵御恶意代码读取私有文件。面向任意不可信仓库的部署应使用容器/独立工作机，并将验收服务与公开测试执行环境物理分离。

## 节点连线工作台

访问 `/engineering`。使用本地已安装的 React Flow，实现节点拖动、缩放、平移、缩略图及点击证据，参考原 WCTP 的节点、端口、依赖连线和循环语义。

- 工程流程：原有九项能力和公开失败反馈环。
- Agent 分工：实际规划的员工依赖图与专业 Skill。
- 候选搜索树：实际父子关系、树编号、深度、访问、公开测试与选定分支。
- 自动化测试：模型生成的步骤说明与实际 pytest 用例结果分别显示。步骤说明不标为已经逐项执行。

执行状态、生成测试数量、原有回归、独立验收、构建和运行检查来自本地运行 JSON，没有预置成功数字。页面不是工作流执行器，不能通过拖动节点绕过宿主关卡；原始证据中的执行顺序决定实际行为。

验收通过后可启动真实应用：

```powershell
.venv-flaskr/Scripts/python.exe -X utf8 scripts/serve-completed-flaskr.py --run <已通过的运行ID> --port 8774
```

预览会重新检查候选哈希，使用独立演示数据库并通过应用路由创建样例文章，不覆盖原始项目数据。

## 实验口径

失败和中断实验必须保留；本轮分别发现了生成测试路径搬迁和 HTML 辅助解析器语义问题。修复的是宿主身份映射与测试生成质量流程，没有修改已经冻结的失败记录。

效果数据至少包括项目与任务来源、模型、冻结测试哈希、候选数、节点深度、真实调用次数/Token、公开通过率、独立验收、原有回归、构建和运行证据。单个项目跑通只证明流程可执行，不能证明多树比单树、线性流程更好。比较算法需要同样项目、故障、测试和预算，多任务多次运行，并分别报告中断和未知费用。

可用 `scripts/search-ablation.py --foundation <已验收运行ID>` 进行对照。复用的五项公开前置产物明确标注 `frozen_foundation_reuse`，没有新推理；后续规划、修复、诊断、审核与评审仍调用真实模型。脚本输出 `paired_tests`，只有冻结测试字节完全一致的运行才纳入成对比较。线性流程与搜索流程的员工分工和调用额度也有差别，这个工程对照不能单独识别 MCTS 的因果收益。为保持来源可核验，复用基础必须含原始公开请求，暂不支持把已有复用轨迹作为下一层基础。
