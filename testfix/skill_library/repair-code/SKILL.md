输入需求、当前位置与代码版本、诊断、新测试及允许修改范围。借鉴 AD 按当前状态和有限动作集生成操作；工程动作是补丁提案，实际应用和验证由控制器执行。

修复行为本身，保留公开接口与已有行为。只修改范围清单内的业务源码；生成测试、原有回归、独立验收、参考答案、评测器与评分阈值均不可修改。不得让 fixture、搜索路径或安装副本跳到另一版本制造通过。

纯函数模式返回现有 `code` 与 `reason` JSON，包含完整模块；执行前由 AST 策略检查函数、导入和纯计算限制。Flaskr 模式按指定文件清单交付源码/补丁，允许工程正常路由、装饰器、模板与数据库访问；不能套用纯函数语法限制，也不能自行扩大文件范围。

`python_package` 仅修改允许的库模块及 CLI 实现文件，保持任务指定的公开 API、命令行兼容性和打包入口。补丁必须绑定当前候选哈希；不得通过改测试、改执行器、改导入路径或换用其它安装副本来制造成功。需要构建配置变动但不在允许范围时，提出有证据的范围问题，不自行扩权。真实 CLI 与 wheel 交付取代此场景无关的 HTTP/SQLite 要求，不改变 Flaskr 原关卡。

输出 `patch_artifact`：基线哈希、修改文件、候选哈希、关联需求/失败、修改理由及需要执行的回归。不得以“模型认为可以”宣称测试通过。版本变化后旧的评审与运行证据作废；保留各轮补丁和失败记录。

发现需求歧义或测试自身错误时提交证据给控制器，暂停依赖该判断的修改。收到策略拒绝后先收窄补丁；收到断言失败后依据新证据修复。最多执行契约配置的轮数，预算耗尽时返回未完成状态与已知问题。

读取 [机器契约](references/contract.json) 查看唯一写权限、前置诊断与失败反馈。此 JSON 权限检查只约束声明的调用；实际进程隔离仍由执行环境负责。
